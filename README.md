# InfiniteCanvas — бесконечный холст для окон Windows

Утилита превращает рабочий стол Windows в бесконечный холст в духе Figma или Obsidian Canvas: вы зажимаете кнопку мыши на **фоне рабочего стола** и тащите — все открытые окна плавно едут вместе, как объекты на полотне. Экран при этом — «камера», смотрящая на кусок огромного виртуального пространства.

Идея восходит к proof-of-concept [WinfiniteCanvas](https://github.com/Nick-de-Bruin/WinfiniteCanvas); эта реализация написана с нуля и заметно надёжнее: виртуальная система координат вместо накопления дельт, батч-перемещение без мерцания, честная обработка DPI, админских окон, полноэкранных приложений и системных окон.

## Возможности

- **Панорамирование холста** — зажмите **среднюю кнопку мыши** или **Alt + левую кнопку** на фоне рабочего стола и тащите. Все окна двигаются синхронно одним батчем (`DeferWindowPos`), без рывков и мерцания.
- **Виртуальные координаты** — у каждого окна есть «истинная» позиция на холсте, у камеры — смещение. Экранная позиция = виртуальная − камера. Ошибки округления не накапливаются: дельта всегда считается от точки начала жеста.
- **Возврат домой** — `Ctrl+Alt+Home` плавно возвращает камеру в точку (0,0), где окна были при запуске.
- **Закладки** — `Ctrl+Alt+Shift+1..4` сохраняет текущую позицию камеры, `Ctrl+Alt+1..4` перелетает к ней. Закладки переживают перезапуск (пишутся в config.ini).
- **Инерция** — после резкого отпускания холст докатывается и мягко останавливается (отключается в конфиге).
- **Режим обзора** — `Ctrl+Alt+O` показывает полупрозрачную миникарту всего холста: прямоугольники окон с заголовками и рамка текущего «окна камеры». Клик по прямоугольнику перелетает к окну. Это осознанная замена зума — см. [Почему нет настоящего зума](#почему-нет-настоящего-зума).
- **Иконка в трее** — обзор, возврат домой, пауза, открытие/перезагрузка конфига, выход.
- **Конфиг** `config.ini` рядом с exe — создаётся автоматически со значениями по умолчанию.

## Требования

- Windows 10 (1703+) или Windows 11, **x64**.
- Для сборки: Visual Studio 2022 (любая редакция) или Build Tools 2022 с воркнагрузкой «Разработка классических приложений на C++».
- Внешних зависимостей нет: чистый Win32 API, C++17, рантайм слинкован статически (`/MT`) — на выходе один самодостаточный `InfiniteCanvas.exe`.

## Скачать готовый exe

На каждый пуш GitHub Actions собирает Release-сборку: вкладка **Actions** → последний зелёный запуск **build** → артефакт **InfiniteCanvas-x64** (внутри exe + config.ini + README).

## Сборка

### Visual Studio 2022

1. Откройте `InfiniteCanvas.sln`.
2. Выберите конфигурацию **Release | x64**.
3. **Build → Build Solution** (Ctrl+Shift+B).
4. Результат: `bin\x64\Release\InfiniteCanvas.exe`.

### Командная строка (без открытия IDE)

Вариант 1 — скрипт (сам найдёт MSBuild через vswhere):

```bat
build.cmd
```

Вариант 2 — msbuild из «Developer Command Prompt for VS 2022»:

```bat
msbuild InfiniteCanvas.sln /m /p:Configuration=Release /p:Platform=x64
```

Вариант 3 — голый cl (тоже из Developer Command Prompt, x64):

```bat
cl /std:c++17 /O2 /MT /EHsc /W4 /utf-8 /DUNICODE /D_UNICODE src\*.cpp ^
   /link /SUBSYSTEM:WINDOWS /OUT:InfiniteCanvas.exe ^
   user32.lib gdi32.lib shell32.lib dwmapi.lib advapi32.lib
mt.exe -manifest app.manifest -outputresource:InfiniteCanvas.exe;1
```

## Запуск

Просто запустите `InfiniteCanvas.exe` — появится иконка в системном трее. Приложение одно-экземплярное: повторный запуск покажет сообщение и выйдет.

### Про права администратора (важно)

Windows (UIPI) запрещает обычному процессу двигать окна процессов с более высокими правами: **Диспетчер задач**, regedit, установщики, всё запущенное «от имени администратора». Это не баг, а механизм безопасности ОС.

InfiniteCanvas это определяет заранее (сравнивая integrity level процессов), молча пропускает такие окна и один раз показывает уведомление в трее. Хотите двигать и их — запустите `InfiniteCanvas.exe` **от имени администратора** (ПКМ → «Запуск от имени администратора»). Манифест намеренно `asInvoker`, чтобы не требовать UAC при каждом запуске.

## Горячие клавиши

| Комбинация | Действие |
|---|---|
| Средняя кнопка мыши + тащить (по фону) | Панорамирование холста |
| `Alt` + ЛКМ + тащить (по фону) | Панорамирование холста |
| `Ctrl+Alt+Home` | Вернуть камеру домой (0,0) |
| `Ctrl+Alt+O` | Режим обзора (миникарта холста) |
| `Ctrl+Alt+1..4` | Перейти к закладке |
| `Ctrl+Alt+Shift+1..4` | Сохранить закладку |
| `Ctrl+Alt+P` | Пауза / возобновление панорамирования |
| `Ctrl+Alt+Shift+Q` | Выход |

В режиме обзора: ЛКМ по окну — перелететь к нему, `Esc` / ПКМ — закрыть.

## Конфиг (config.ini)

Лежит рядом с exe, создаётся автоматически. Кодировка — UTF-16 LE (не меняйте при редактировании). После правок: трей → «Перезагрузить конфиг».

| Секция | Ключ | По умолчанию | Описание |
|---|---|---|---|
| Pan | MiddleButton | true | Панорамирование средней кнопкой |
| Pan | AltLeftButton | true | Панорамирование Alt+ЛКМ |
| Pan | Sensitivity | 1.0 | Множитель смещения холста |
| Pan | DragThresholdPx | 4 | Порог (px) отличия клика от перетаскивания |
| Inertia | Enabled | true | Инерция после отпускания |
| Inertia | Friction | 5.0 | Затухание, 1/сек (больше — быстрее стоп) |
| Inertia | MinVelocity | 250 | Мин. скорость отпускания для инерции, px/с |
| Camera | FlightMs | 180 | Длительность перелёта камеры, мс (0 = мгновенно) |
| Filter | SkipUntitled | true | Пропускать окна без заголовка |
| Filter | SkipFullscreen | true | Не двигать полноэкранные окна |
| Filter | SkipMaximized | false | Не двигать развёрнутые окна |
| Filter | ExcludeClasses | Rainmeter… | Чёрный список классов окон (через `;`) |
| Filter | ExcludeTitles | — | Чёрный список подстрок заголовков (через `;`) |
| Filter | BackgroundClasses | Progman;WorkerW | Классы окон-фона (откуда стартует жест) |
| Overview | Enabled / Alpha | true / 235 | Режим обзора и его непрозрачность |
| Hotkeys | EnableBookmarks | true | Регистрировать ли Ctrl+Alt+1..4 (могут конфликтовать с приложениями) |
| Debug | LogToFile | false | Лог в `infinitecanvas.log` рядом с exe |
| Bookmarks | Slot1..4 | — | Заполняется автоматически |

Системные окна (`Shell_TrayWnd`, `Progman`, `WorkerW`, панель задач, меню и т.п.) захардкожены в чёрный список в коде и не отключаются конфигом — иначе можно развалить рабочий стол.

## Почему нет настоящего зума

Живое Win32-окно нельзя визуально отмасштабировать: `SetWindowPos` с изменением размера — это не зум, а re-layout, который ломает вёрстку приложений, а DWM-трансформации недоступны обычному процессу. Поэтому основной режим — только панорамирование, а «отдалиться и увидеть всё» даёт режим обзора (`Ctrl+Alt+O`): схематичная миникарта всего холста с мгновенным перелётом к любому окну. Если когда-нибудь появится экспериментальный зум — он будет в отдельной ветке и с явным предупреждением.

## Как это устроено

```
src/
├── main.cpp           — wWinMain: single-instance, DPI-awareness, запуск App
├── App.*              — ядро: скрытое окно, камера (пан/инерция/перелёт), хоткеи, трей-меню, таймеры
├── PanController.*    — глобальный хук WH_MOUSE_LL, распознавание жеста, замер скорости
├── WindowTracker.*    — перечисление/фильтрация окон, виртуальные координаты, батч DeferWindowPos
├── OverviewWindow.*   — полупрозрачный оверлей-миникарта
├── TrayIcon.*         — иконка в трее (рисуется в рантайме, без .ico)
├── Config.*           — config.ini через Profile API
└── Common.*           — сообщения, лог, DPI-хелперы
```

Ключевые решения:

- **Хук не делает тяжёлой работы.** Колбэк `WH_MOUSE_LL` только меняет состояние жеста и постит коалесцированное сообщение главному окну — иначе система считала бы хук «медленным» и отключила его, а курсор бы лагал глобально.
- **Начало жеста определяется честным hit-test'ом**: `WindowFromPoint` → `GetAncestor(GA_ROOT)` → класс `Progman`/`WorkerW`. Клик по окну приложения никогда не перехватывается.
- **Батч-перемещение**: один проход `BeginDeferWindowPos`/`EndDeferWindowPos` на кадр; если батч падает (например, из-за защищённого окна) — fallback на поштучный `SetWindowPos` с пометкой виновника как неперемещаемого. Зависшие окна (`IsHungAppWindow`) пропускаются, чтобы не стопорить весь батч.
- **Список окон кешируется** и обновляется по событиям `SetWinEventHook` (появление/скрытие/сворачивание окон, конец перетаскивания пользователем) плюс страховочный таймер раз в 2 с — `EnumWindows` не дёргается каждый кадр.
- **Фильтрация окон**: невидимые, свёрнутые, cloaked (UWP-призраки и окна других виртуальных рабочих столов — через `DWMWA_CLOAKED`), tool-окна, полноэкранные, окна из чёрных списков, окна повышенных процессов.

## Известные ограничения

- **Окна с правами выше наших не двигаются** (Диспетчер задач и др.) — механизм UIPI. Решение: запуск от администратора. Уведомление показывается один раз.
- **Настоящего зума нет** — см. выше; вместо него режим обзора.
- **Полноэкранные приложения и игры** по умолчанию исключены (`SkipFullscreen=true`): их перемещение ведёт себя непредсказуемо.
- **Только текущий виртуальный рабочий стол** — окна других десктопов cloaked и не трогаются.
- **Развёрнутые (maximized) окна** двигаются, но Windows считает их «развёрнутыми» на старом мониторе; после перетаскивания поведение кнопки «Развернуть» может выглядеть странно. Отключается через `SkipMaximized=true`.
- **Средний клик и Alt+клик по фону рабочего стола перехватываются** приложением (даже без движения) — это плата за отсутствие случайных рамок выделения. Обычный ЛКМ по столу и иконкам работает как всегда.
- **Alt+ЛКМ по иконкам рабочего стола** запускает панорамирование, а не перетаскивание иконки (иконки — часть фона `Progman`). Иконки перетаскиваются обычной ЛКМ.
- **Wallpaper Engine / Rainmeter**: базовые классы Rainmeter уже в чёрном списке; если ваш оверлей уезжает вместе с холстом — добавьте его класс окна в `ExcludeClasses` (класс можно узнать утилитой типа Spy++ или WinSpy).
- **Глобальные хоткеи могут конфликтовать** с другими приложениями — при неудачной регистрации пишется лог; закладки можно выключить (`EnableBookmarks=false`).
- **Окна, «прилипшие» краем за пределы экрана**, Windows может слегка скорректировать при возврате — модель это абсорбирует при следующей синхронизации.
- При 30–50+ окнах перемещение остаётся плавным (один батч на кадр); совсем экстремальные количества окон упрутся в сам `EndDeferWindowPos`.
