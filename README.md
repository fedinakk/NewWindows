# InfiniteCanvas — бесконечный холст для окон Windows

Утилита превращает рабочий стол Windows в бесконечный холст в духе Figma или Obsidian Canvas: зажали **Ctrl+Alt + среднюю кнопку** — и тащите всё рабочее пространство; крутанули **Ctrl+Alt + колесо** — и отдалились, чтобы увидеть больше окон разом. Экран — это «камера» со смещением и масштабом, смотрящая на кусок огромного виртуального пространства. За окнами рисуется собственное полотно с сеткой, которое панорамируется и зумится вместе с камерой — ощущение именно «я двигаюсь по бесконечному рабочему столу», а не «окна ползают по статичным обоям».

Идея восходит к proof-of-concept [WinfiniteCanvas](https://github.com/Nick-de-Bruin/WinfiniteCanvas); эта реализация написана с нуля и заметно надёжнее.

## Возможности

- **Панорамирование холста** — `Ctrl+Alt` + зажатая средняя кнопка: работает из любого места, даже поверх активного окна. Дополнительно (включено по умолчанию): средняя кнопка или `Alt+ЛКМ` на фоне рабочего стола. Все окна двигаются одним батчем (`DeferWindowPos`), без мерцания.
- **Зум** — `Ctrl+Alt` + колесо мыши: геометрический зум рабочего пространства с якорем под курсором. При отдалении окна уменьшаются и сближаются — на экран влезает больше окон; при приближении наоборот. Колесо при зажатом `Ctrl+Alt` принадлежит холсту **глобально** — событие поглощается до того, как дойдёт до активного приложения (Ctrl-зум браузера не сработает — так задумано).
- **Подложка-полотно** — собственный слой в цепочке обоев Windows (за всеми окнами, позади значков рабочего стола): тёмное полотно с точечной сеткой, живущее в координатах холста. Панель задач всегда остаётся на месте.
- **Высокочастотный цикл** — инерция и перелёты камеры идут через high-resolution waitable timer с целевыми 240 FPS (настраивается), а само панорамирование — напрямую от событий мыши без искусственного троттлинга. `SetTimer` с его потолком ~66 Гц не используется.
- **FPS-оверлей** — `Ctrl+Alt+F`: полупрозрачный индикатор в углу с реальной частотой обновления холста, frame-time, масштабом и числом окон.
- **Виртуальные координаты** — единая трансформация `экран = (виртуальные − смещение) × масштаб` через хелперы `VirtualToScreen`/`ScreenToVirtual`; ошибки округления не накапливаются.
- **Возврат домой** — `Ctrl+Alt+Home`: камера плавно возвращается в точку (0,0) с масштабом 100% — раскладка на момент запуска.
- **Закладки** — `Ctrl+Alt+Shift+1..4` сохраняет позицию камеры **вместе с масштабом**, `Ctrl+Alt+1..4` перелетает к ней. Переживают перезапуск.
- **Инерция** — после резкого отпускания холст докатывается и мягко останавливается; при зуме во время инерции экранная скорость сохраняется.
- **Режим обзора** — `Ctrl+Alt+O`: полупрозрачная миникарта всего холста с рамкой камеры и текущим масштабом; клик — перелёт к окну.
- **Иконка в трее**, конфиг `config.ini` рядом с exe.

## Требования

- Windows 10 (1703+) или Windows 11, **x64**.
- Для сборки: Visual Studio 2022 (любая редакция) или Build Tools 2022 с воркнагрузкой «Разработка классических приложений на C++».
- Внешних зависимостей нет: чистый Win32 API, C++17, рантайм слинкован статически (`/MT`) — на выходе один самодостаточный `InfiniteCanvas.exe`.

## Скачать готовый exe

На каждый пуш GitHub Actions собирает Release-сборку: вкладка **Actions** → последний зелёный запуск **build** → артефакт **InfiniteCanvas-x64** (внутри exe + config.ini + README).

## Сборка

### Visual Studio 2022

1. Откройте `InfiniteCanvas.sln`.
2. Выберите конфигурацию **Release | x64**.
3. **Build → Build Solution** (Ctrl+Shift+B).
4. Результат: `bin\x64\Release\InfiniteCanvas.exe`.

### Командная строка (без открытия IDE)

Вариант 1 — скрипт (сам найдёт MSBuild через vswhere):

```bat
build.cmd
```

Вариант 2 — msbuild из «Developer Command Prompt for VS 2022»:

```bat
msbuild InfiniteCanvas.sln /m /p:Configuration=Release /p:Platform=x64
```

Вариант 3 — голый cl (тоже из Developer Command Prompt, x64):

```bat
cl /std:c++17 /O2 /MT /EHsc /W4 /utf-8 /DUNICODE /D_UNICODE src\*.cpp ^
   /link /SUBSYSTEM:WINDOWS /OUT:InfiniteCanvas.exe ^
   user32.lib gdi32.lib shell32.lib dwmapi.lib advapi32.lib winmm.lib
mt.exe -manifest app.manifest -outputresource:InfiniteCanvas.exe;1
```

## Запуск

Просто запустите `InfiniteCanvas.exe` — появится иконка в системном трее. Приложение одно-экземплярное: повторный запуск покажет сообщение и выйдет.

### Про права администратора (важно)

Windows (UIPI) запрещает обычному процессу двигать окна процессов с более высокими правами: **Диспетчер задач**, regedit, установщики, всё запущенное «от имени администратора». Это не баг, а механизм безопасности ОС.

InfiniteCanvas это определяет заранее (сравнивая integrity level процессов), молча пропускает такие окна и один раз показывает уведомление в трее. Хотите двигать и их — запустите `InfiniteCanvas.exe` **от имени администратора**. Манифест намеренно `asInvoker`, чтобы не требовать UAC при каждом запуске.

## Управление

| Комбинация | Действие |
|---|---|
| `Ctrl+Alt` + средняя кнопка + тащить | **Панорамирование** — из любого места, поверх любого окна |
| `Ctrl+Alt` + колесо мыши | **Зум** к точке под курсором (глобально, перехватывается у приложений) |
| Средняя кнопка + тащить (по фону стола) | Панорамирование (дополнительный жест, отключается в конфиге) |
| `Alt` + ЛКМ + тащить (по фону стола) | Панорамирование (дополнительный жест, отключается в конфиге) |
| `Ctrl+Alt+Home` | Домой: смещение (0,0), масштаб 100% |
| `Ctrl+Alt+O` | Режим обзора (миникарта холста) |
| `Ctrl+Alt+F` | FPS-оверлей вкл/выкл |
| `Ctrl+Alt+1..4` | Перейти к закладке (позиция + масштаб) |
| `Ctrl+Alt+Shift+1..4` | Сохранить закладку |
| `Ctrl+Alt+P` | Пауза / возобновление перехвата мыши |
| `Ctrl+Alt+Shift+Q` | Выход |

В режиме обзора: ЛКМ по окну — перелететь к нему, `Esc` / ПКМ — закрыть.

Пока зажат `Ctrl+Alt`, колесо и средняя кнопка **не доходят до приложений** — это осознанное поведение (см. `[Zoom] CaptureWheel`). Системные комбинации уровня `Ctrl+Alt+Del` перехватить невозможно, и мы не пытаемся. Стрелки и прочая клавиатура не трогаются (чтобы не конфликтовать с драйверными шорткатами вроде поворота экрана Intel).

## Честные оговорки (важно прочитать)

### Зум — геометрический, не пиксельный

Win32 не умеет дёшево и без искажений визуально отмасштабировать живое интерактивное окно, как объект в Figma. Поэтому зум здесь **геометрический**: масштабируются рамки и раскладка окон — при отдалении каждое окно получает `SetWindowPos` с меньшими позицией **и размером**, и приложение само переверстывает содержимое под новый размер (текст не «уменьшается», а перекомпоновывается). Следствия:

- **Минимальные размеры окон уважаются.** Окно, которое отказалось ужиматься (диалоги, окна с большим min-size), остаётся на своём минимуме и просто корректно позиционируется. Приложение запоминает фактический минимум каждого окна и не долбит его повторными попытками.
- **Не ресайзятся**: окна без изменяемой рамки (`WS_THICKFRAME`), развёрнутые (maximized) и полноэкранные окна — они только позиционируются либо пропускаются.
- DWM-thumbnails как «настоящий» зум не используются намеренно: превью неинтерактивны, это тупик.
- Окно, открытое при масштабе ≠100%, принимается на холст со своим текущим экранным размером (без визуального скачка); его «канвасный» размер при этом отличается от натурального — при возврате к 100% оно может оказаться крупнее/мельче, чем было бы при открытии на 100%.

### 240 FPS — про цикл, а не про перерисовку чужих окон

`TargetFPS=240` — целевая частота нашего цикла анимации и обработки ввода (панорамирование вообще обрабатывается на частоте событий мыши). Фактическая **визуальная** плавность ограничена композитором DWM (кадры экрана) и стоимостью `DeferWindowPos` при большом числе окон: реальная перерисовка чужих окон может обновляться реже. Приложение никогда не гонит `DeferWindowPos` вхолостую — окна трогаются только когда их целевой прямоугольник реально изменился. FPS-оверлей (`Ctrl+Alt+F`) показывает именно частоту обновления холста — по нему видно, где узкое место.

### «Замена рабочего стола» — визуальная, а не подмена оболочки

Подложка-полотно встраивается в штатную цепочку обоев Windows (`Progman`/`WorkerW`, тот же механизм, что у Wallpaper Engine): она лежит **за всеми окнами и позади значков рабочего стола**, значки остаются видимыми и рабочими, панель задач (`Shell_TrayWnd`, `Shell_SecondaryTrayWnd`) не двигается, не зумится и не перекрывается — никогда. Обои при включённой подложке закрыты нашим полотном; при выходе из приложения всё возвращается как было.

Категорически **не** делается: замена `explorer.exe` как shell, правка `Winlogon\Shell`, убийство Explorer. Это сломало бы систему и отняло бы ту самую панель задач. Наша «замена рабочего стола» — визуально-поведенческий слой поверх работающего Explorer.

Устройство `Progman`/`WorkerW` отличается между билдами Win10/11 (включая Win11 24H2); используются несколько стратегий поиска слоя обоев, а если ни одна не сработала — подложка тихо отключается (пишется в лог), не рискуя закрыть значки. При перезапуске Explorer подложка автоматически пересоздаётся.

## Как это устроено

```
src/
├── main.cpp           — wWinMain: single-instance, DPI-awareness, запуск App
├── App.*              — ядро: камера (пан/зум/инерция/перелёт), высокочастотный
│                        цикл кадров, хоткеи, трей-меню, FPS-статистика
├── PanController.*    — хук WH_MOUSE_LL: жесты, глобальный перехват Ctrl+Alt+колеса
├── WindowTracker.*    — окна: фильтрация, виртуальные прямоугольники (double),
│                        батч DeferWindowPos с позицией и размером, min-size клампы
├── CanvasBackdrop.*   — полотно в слое обоев (Progman/WorkerW), сетка pattern-brush
├── OverviewWindow.*   — оверлей-миникарта
├── FpsOverlay.*       — click-through индикатор FPS
├── TrayIcon.*         — иконка в трее (рисуется в рантайме)
├── Config.*           — config.ini через Profile API
└── Common.*           — Camera и трансформации, сообщения, лог, DPI-хелперы
```

Ключевые решения:

- **Единая трансформация** `screen = (virt − offset) × scale` живёт в `Common.h` (`VirtualToScreen`/`ScreenToVirtual`) и используется всеми подсистемами — окнами, зумом, обзором, подложкой. Координаты — физические пиксели (процесс per-monitor DPI-aware), DPI-коэффициент в трансформации не участвует и не может примениться дважды.
- **Хук не делает тяжёлой работы**: колбэк `WH_MOUSE_LL` только меняет состояние и постит коалесцированные сообщения — иначе Windows отключит «медленный» хук.
- **Цикл кадров**: `MsgWaitForMultipleObjectsEx` ждёт одновременно очередь сообщений и high-resolution waitable timer; `timeBeginPeriod(1)` поднимает разрешение таймеров (парный `timeEndPeriod` при выходе); dt считается по `QueryPerformanceCounter`.
- **Зум к точке**: `cam' = V − P/scale'`, где `V` — виртуальная точка под курсором `P`. Работает на любом мониторе и у краёв экрана, т.к. считается в глобальных экранных координатах.
- **Батч-перемещение**: один `BeginDeferWindowPos`/`EndDeferWindowPos` на изменение камеры, позиция и размер сразу; fallback на поштучный `SetWindowPos`; зависшие окна пропускаются.
- **Список окон кешируется**, обновляется по `SetWinEventHook` + таймер 2 с; во время панорамирования re-enumerate ограничен (раз в 200 мс), но само движение окон не троттлится.

## Известные ограничения

- **Окна с правами выше наших не двигаются** (Диспетчер задач и др.) — UIPI; запуск от администратора решает. Уведомление показывается один раз.
- **Содержимое окон не масштабируется пиксель-в-пиксель** — см. «Честные оговорки»; зум геометрический.
- **Полноэкранные приложения и игры** по умолчанию исключены; только текущий виртуальный рабочий стол.
- **Развёрнутые (maximized) окна** двигаются при панорамировании, но не ресайзятся при зуме.
- **Ctrl+Alt+колесо и Ctrl+Alt+средняя кнопка недоступны приложениям**, пока работает InfiniteCanvas (это фича; `Ctrl+Alt+P` — пауза, если жест нужен приложению).
- **Alt+ЛКМ по значкам рабочего стола** запускает панорамирование, а не перетаскивание значка; значки перетаскиваются обычной ЛКМ.
- **Wallpaper Engine**: наша подложка конкурирует с ним за один и тот же слой WorkerW — одновременно лучше не использовать (`[Backdrop] Enabled=false`, если обои от WE важнее).
- **Глобальные хоткеи могут конфликтовать** с другими приложениями; закладки отключаются (`EnableBookmarks=false`).
- При очень большом числе окон узким местом становится сам `EndDeferWindowPos` — двигаем только реально изменившиеся окна, но физику перерисовки чужих процессов не обойти.
